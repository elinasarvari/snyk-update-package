## 1. Components

You talk to an assistant (GitHub Copilot or Claude Code). The `/dep-*` commands are thin entry points: all real
instructions live in `toolkit/`, and all real work is done by the scripts, which talk to the outside world.

```mermaid
%%{init: {"flowchart": {"wrappingWidth": 640}}}%%
flowchart TB
    user(["You"])
    ide["<b>1 · Your assistant</b><br/>GitHub Copilot (VS Code, Local session) · Claude Code (terminal or VS Code)"]
    entry["<b>2 · Commands</b>: generated by tools/generate-entrypoints.py<br/>.github/: prompts · agents · skills · instructions (Copilot)<br/>.claude/ + CLAUDE.md: skills · agents · settings.json (Claude)"]
    toolkit["<b>3 · toolkit/</b>: the single source of truth<br/>WORKFLOW.md (rules, token budget) · RUN.md · LOGIN.md<br/>phases/0-clone … 6-publish · roles/ (analyst · applier · verifier) · templates/"]
    scripts["<b>4 · toolkit/scripts/</b>: tested code, bash + PowerShell twins<br/>repos.py (clones, workflow branches) · workflows.py (wf-NNN, steps, INDEX)<br/>snyk-login · snyk-scan · parse-snyk.py · maven-facts · verify-repo · script-helpers.py"]
    ext[("<b>5 · Outside world</b><br/>Snyk (OAuth2 / SSO) · Git hosting (clone, push, PR)<br/>Maven Central · official docs (migration guides, cached)")]

    user --> ide --> entry --> toolkit --> scripts --> ext

    classDef layer fill:#f4f6f8,stroke:#5d6d7e,color:#1c2833,text-align:left
    class ide,entry,toolkit,scripts layer
```

| Layer | What it is | Why it's separate |
|-------|------------|-------------------|
| **Entry points** (`.github/`, `.claude/`) | The `/dep-*` commands for each assistant: a few lines each, pointing at `toolkit/` | Both assistants behave the same; they're regenerated from one spec, so they can't drift |
| **Toolkit** (`toolkit/*.md`) | The procedures: what each step does, when to stop, the rules | One place to change behaviour, for both assistants |
| **Scripts** (`toolkit/scripts/`) | Everything that can be done by code: cloning, branching, scanning, parsing, building, tracking | Deterministic and tested, instead of left to the AI |
| **Subagents** (`roles/`) | Focused helpers: analyse one package in one repo, apply the plan in one repo, verify one repo | Run in parallel; each has strict limits (read-only, or edit only what the plan says) |

## 2. The workflow: steps, stops and gates

Each run is **Workflow N** (`wf-NNN`). `/dep-run` moves through the steps by itself and stops only where it needs
you. The two red gates never pass without you.

```mermaid
stateDiagram-v2
    direction TB
    [*] --> Clone: /dep-run repo
    Clone: 0 Clone · repo cloned, branch deps/wf-NNN from latest main
    Scan: 1 Snyk scan · every flagged package
    Login: Snyk login · browser OAuth2 / SSO
    Inventory: 2 Inventory · current vs target, what moves, baseline build
    Analyze: 3 Impact and plan · what breaks and where, ordered steps
    Approve: Plan approval
    Apply: 4 Apply · changes on deps/wf-NNN, not committed
    Verify: 5 Verify · build, tests, app boot vs baseline, Snyk re-scan
    Review: Review results
    Publish: 6 Publish · commit, push branch, open PR
    Blocked: Stopped · needs a decision

    Clone --> Scan
    Scan --> Login: CLI not logged in
    Login --> Scan: signed in, retry
    Scan --> Inventory: findings with a fix
    Scan --> [*]: no findings
    Inventory --> Analyze
    Inventory --> Blocked: version mismatch, red baseline, missing target
    Blocked --> Inventory: your decision
    Analyze --> Approve
    Approve --> Apply: you reply approve
    Approve --> Analyze: you ask for changes
    Apply --> Verify
    Verify --> Review
    Review --> Analyze: red, add fix steps, re-approve
    Review --> Publish: you run /dep-publish
    Publish --> [*]

    classDef gate fill:#fde2e1,stroke:#c0392b,color:#7b241c
    classDef auto fill:#e8f4fd,stroke:#2e86c1,color:#1b4f72
    class Approve,Review,Publish gate
    class Clone,Scan,Inventory,Analyze,Apply,Verify auto
```

| Step | Command | Changes the repo? | Stops for you when |
|------|---------|-------------------|--------------------|
| 0 Clone | `/dep-clone` | creates/switches the clone's branch `deps/wf-NNN` | clone failed, no main branch, or another workflow's unpublished changes are there |
| 1 Snyk scan | `/dep-scan` | no | no Snyk CLI, or the login didn't complete |
| 2 Inventory | `/dep-inventory` | no (build output only) | a discrepancy, a missing target version, or a red baseline |
| 3 Impact + plan | `/dep-analyze` | no | **always**: approve the plan |
| 4 Apply | `/dep-apply` | **yes**, on `deps/wf-NNN`, uncommitted | a step stays red after two fix attempts |
| 5 Verify | `/dep-verify` | no (build output only) | **always**: review the results |
| 6 Publish | `/dep-publish` | commits and pushes the branch | only runs when **you** start it |

## 3. One `/dep-run`, in order

Who calls whom during a typical run. Everything an assistant decides is backed by a script call, and every step
writes its result to a file before moving on.

```mermaid
sequenceDiagram
    autonumber
    actor You
    participant A as Assistant<br/>(Copilot / Claude)
    participant W as workflows.py
    participant R as repos.py
    participant S as snyk-login / snyk-scan
    participant SA as Subagents<br/>(analyst · applier · verifier)
    participant V as verify-repo
    participant X as Snyk · Git · docs

    You->>A: /dep-run inventory-service
    A->>R: ensure inventory-service
    A->>W: new / find-open → Workflow N (wf-NNN)
    A->>R: --workflow N clone
    R->>X: git clone / fetch
    R-->>A: on deps/wf-NNN from origin/main
    A->>S: snyk-scan --workflow N
    alt CLI not logged in
        S-->>A: exit 126
        A->>S: snyk-login (browser opens)
        You->>X: sign in with company SSO
        S-->>A: Logged in as you@company.com
        A->>S: snyk-scan again
    end
    S->>X: snyk test --all-projects --exclude=target,…
    S-->>A: raw JSON → parse-snyk → findings.md
    A->>V: baseline build + tests (+ boot)
    A->>SA: dependency-analyst per (upgrade, repo)
    SA->>X: migration guides (once, then from the cache)
    SA-->>A: analysis files → 03-impact.md, 03-plan.md
    A-->>You: ⏸ review 03-plan.md, reply "approve"
    You->>A: approve
    A->>SA: upgrade-applier (edits the clone on deps/wf-NNN)
    A->>SA: repo-verifier → verify-repo vs baseline
    A-->>You: ⏸ 05-verification.md: green? run /dep-publish
    You->>A: /dep-publish wf-NNN
    A->>X: commit, push deps/wf-NNN, open PR
    Note over A,W: every step: workflows.py phase / next / log → STATUS.md + INDEX.md
```

## 4. Where every file lives

Three places, with clear boundaries: what's shared in git, what stays on your machine, and the repo you're fixing.

```mermaid
flowchart LR
    subgraph tracked["snyk-update-package: in git (keep the repo private)"]
        direction TB
        t1["toolkit/<br/>procedures · scripts · templates"]
        t2[".github/ · .claude/ · CLAUDE.md<br/>commands and assistant settings"]
        t3["tests/ · docs/ · README.md"]
        t4["repos/repos.txt<br/>(ships with examples only)"]
        l1["workflows/wf-NNN-…/<br/>STATUS · 01 … 06 · findings · analysis<br/>pushed by /dep-save"]
        l3["workflows/INDEX.md · _research/"]
    end

    subgraph local["snyk-update-package: your machine only (git-ignored)"]
        direction TB
        l2["raw Snyk JSON · logs · .last-id"]
        l4[".claude/settings.local.json<br/>your permission answers"]
    end

    subgraph clone["repos/name/: the repo you're fixing (its own git repo)"]
        direction TB
        c1["main"]
        c2["deps/wf-001 · deps/wf-002 …<br/>ONLY the planned code and pom changes"]
        c3["target/ · build/ (build output, never read for analysis)"]
    end

    subgraph remote["Remote"]
        direction TB
        r1[("the repo's GitHub / Bitbucket<br/>PR from deps/wf-NNN into main")]
        r2[("Snyk")]
        r3[("snyk-update-package on GitHub<br/>(private)")]
    end

    yours["~/repos/name<br/>your own checkout"]

    t1 -->|reads / runs| clone
    t1 -->|writes, /dep-save pushes| l1
    c2 -->|/dep-publish| r1
    t1 -->|scan, login| r2
    l1 -->|/dep-save| r3
    yours -. "never touched; only used to look up the URL" .-> t4
```

| Rule | Enforced by |
|------|-------------|
| The repo gets **only** the planned code and package changes; every document, log and report goes to `workflows/` | the procedures, and `verify-repo` reporting anything a build leaves behind (`left_in_repo`); tested end to end |
| Your own checkouts are never touched | `repos.py` only reads their URL; tested |
| Build output and dependencies (`target/`, `node_modules/`, `.git/` …) are never searched, scanned or edited | `toolkit/ignore-dirs.txt` → Snyk `--exclude`, pom discovery, `.vscode/settings.json`, `.claude/settings.json` |
| Workflow records go to **this** repo's GitHub, never raw Snyk JSON or logs; only while the repo is private | `workflows.py save` (commits only `workflows/`, refuses on a public repo); `.gitignore`; tested |
| Nothing is committed or pushed to a **target repo** except by `/dep-publish`, which you start | manual-only commands (Claude) and send-only-by-you handoffs (Copilot); tested |

## 5. What each step reads and writes

All inside `workflows/wf-NNN-<repo>/` unless noted. Each step reads the previous step's files, not the chat, which
is why a run can resume in a fresh chat at any stop.

```mermaid
flowchart LR
    s0["0 Clone"] --> s1["1 Scan"] --> s2["2 Inventory"] --> s3["3 Impact + plan"] --> s4["4 Apply"] --> s5["5 Verify"] --> s6["6 Publish"]

    s0 -. writes .-> f0[/"STATUS.md · repos.txt<br/>(clone on deps/wf-NNN)"/]
    s1 -. writes .-> f1[/"snyk/*.json → 01-snyk-findings.md<br/>snyk/findings.csv"/]
    s2 -. writes .-> f2[/"02-inventory.md · facts/<br/>verification/baseline/"/]
    s3 -. writes .-> f3[/"03-impact.md · 03-plan.md<br/>analysis/ · ../_research/"/]
    s4 -. writes .-> f4[/"04-apply-log.md<br/>(code changes in the clone)"/]
    s5 -. writes .-> f5[/"05-verification.md<br/>verification/after/"/]
    s6 -. writes .-> f6[/"06-publish.md<br/>(commit + PR in the repo)"/]
```

| Step | Reads | Writes |
|------|-------|--------|
| 0 Clone | `repos/repos.txt` (or the workflow's `repos.txt`) | `STATUS.md`, the clone on `deps/wf-NNN` |
| 1 Snyk scan | the clone | `snyk/<repo>.json` (raw), `snyk/findings.{md,csv,json}`, `01-snyk-findings.md` |
| 2 Inventory | `01-snyk-findings.md` (scope), the clone's poms | `facts/<repo>/`, `verification/baseline/<repo>/`, `02-inventory.md` |
| 3 Impact + plan | `02-inventory.md`, `facts/`, `_research/`, the clone's code (`git grep`) | `analysis/`, `03-impact.md`, `03-plan.md` (+ `_research/` the first time) |
| 4 Apply | `03-plan.md` (approved) | code changes in the clone, `04-apply-log.md` |
| 5 Verify | the clone, `verification/baseline/`, `03-impact.md` | `verification/after/`, `05-verification.md` |
| 6 Publish | `04-apply-log.md`, `03-impact.md`, `05-verification.md` | a commit + PR in the repo, `06-publish.md` |
